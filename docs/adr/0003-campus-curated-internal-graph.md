# 0003 校园内部连通路网校核层

状态：已接受

日期：2026-06-13

## 背景

评分标准要求景区和学校内部建立道路图，并基于内部道路图完成路线规划和附近设施查询。北京大学校园已经通过 `database/imports/internal_navigation_pku.sql` 导入 OSM 节点、建筑、设施和道路边，数据进入正式的 `graph_nodes`、`graph_edges`、`facilities` 表。

实际验收时发现一个工程问题：开放地图中的校园内部路网存在大量断裂连通片区。算法本身是 Dijkstra，但如果起点和设施落在不同碎片里，系统只能返回不可达，附近设施排序也只能覆盖很小范围。继续在前端美化折线不能解决这个问题。

## 决策

在保留 OSM 原始导入的基础上，为北京大学新增一层人工校核的校园主路网 seed：

- 文件：`database/seeds/seed_pku_curated_map.sql`
- 生成器：`scripts/gen_pku_curated_map.py`
- 主路网节点和边继续进入 `graph_nodes`、`graph_edges`
- 分类设施继续进入 `facilities`
- 设施接入点继续通过短边接入路网
- 主路网来源标记为 `campus_curated`
- 设施接入短边来源标记为 `generated`

后端路线质量判断改为接受所有非 `generated` 的正式道路来源，而不是只接受 `osm`。这样可以同时支持 OSM 真实导入边和人工校核的校园主路网边，同时仍然把设施接入短边识别为辅助连接段。

## 影响

- 北京大学内部设施查询可以从校园入口、建筑、景点或地图点选位置出发，按内部路网 Dijkstra 计算实际步行距离。
- 页面展示的校园内部道路不再只依赖碎片化 OSM 连通块，验收时能演示“从某个场所查附近设施并排序”。
- 数据来源更诚实：人工校核边不会伪装成 OSM，答辩时可以明确说明“原始地图导入 + 校核连通层”的工程处理。
- 后续如果继续补清华或其它校园，可以复用同一模式：先导入真实地图数据，再补少量人工校核主路网，全部进入正式数据库表，不新建第二套路网。
